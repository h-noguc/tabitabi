## 決定
| 論点 | 決定 | 理由 |
|---|---|---|
| want/been の単位 | **メンバーごと** | 1人ずつ持てば2人分の見え方（2人とも行った、片方だけ行きたい等）は計算で作れる。2人で1つにすると、後から分けられない |
| 「行った」 | 印として持たず、**そのメンバーが参加した訪問記録が1件以上あるか**で決める | 「行った」の情報を1か所にし、食い違いを防ぐ。行ったうえで「また行きたい」も表せる |
| 訪問記録 | **訪問ごとに1件**。項目は日付（空欄可）・参加者・メモから始め、評価や写真は必要になってから足す | 最終訪問日だけの形で始めると、過去の訪問は復元できない。項目は後から足せる |
| 関心 | メンバーごとに 行きたい / 保留 / もう行かない、とお気に入り | 人によって違う情報だから |
| 閉店 | 場所の営業状況（営業中 / 閉店 / 不明） | 誰から見ても同じ、場所そのものの事実だから |
| 共有の範囲 | 場所ごとに「共有」か「自分だけ」 | 自分だけの場所も持ちたい |
| 持ち主 | 場所を追加した人 | 外したときの戻り先を決めるため |
| 外す | 共有の場所を外すと、**持ち主だけの場所に戻る**。相手の関心は消える。訪問記録は持ち主の側に残す | 誰が外しても、追加した人のデータは失われない |
| 削除 | 持ち主が削除するとゴミ箱に入り、戻せる | 誤操作から戻せるようにする |
| 編集 | 共有の場所は2人とも編集できる。誰が最後に変えたかを残す | |
| メモ | 場所に1つ（共有）。自分だけのメモは持たない | 必要ない |
| 二重登録 | 共有の中で、同じ外部ID、または近い座標で似た名前があれば、登録時に「すでにあります」と出す。自分だけの場所は別に持ってよい | 後からまとめるより、登録時に防ぐ方が簡単 |
| 場所データ | 名前・座標・住所は自分たちのデータとして持ち、外部ID は参照として持つ（0005） | |
| 最寄り駅・出口 | 場所に付く付加情報として持つ。座標から計算し直せる | 「行く時に、どの出口から行くかを見て決めたい」（前の Places セッションでの要望） |

## 暫定（一旦今のまま）
- 分類は Notion の Places DB（Personal OS）にある形を引き継ぐ: カテゴリ（Restaurant / Cafe / Bar / Hotel / Shop / Spot / Other、1つ）、コンテキスト（デート / 旅行 / 誕生日 / 一人 / 友人 / 仕事、複数）、リスト（Notion の Project にあたる）、お気に入り
- この分類を決めた経緯の記録はローカルの会話ログにあり、まだ確認していない。確認したら見直す

## 次に必要になる条件
- 評価・写真: 使ってみて欲しくなったとき（写真は保存先・費用・位置情報のメタデータを決めてから）
- 重複を後からまとめる機能: 登録時の防止をすり抜けた重複が実際に出たとき
