# 0009 GitHub Pro にして main をルールセットで守る

状態: 決定（2026-10-26）
判断者: 自分
議論: https://claude.ai/code/session_01RRsWb1PMfgKNATkiZKYMQQ

## 背景
非公開レポでブランチ保護・ルールセットを使うには GitHub Pro 以上が必要（GitHub Docs「About protected branches」「About rulesets」、2026-10-26 確認）。無料のままだと、CI が赤の PR をマージでき、Claude GitHub App の書き込み権限で AI が main に直接 push できてしまう。

## 決定
GitHub Pro にし、main にルールセットを設定する。

| ルール | 設定 | 理由 |
|---|---|---|
| PR を必須にする | ON。必要な承認数は 0 | 1人開発では自分の PR を自分で承認できない。マージする操作そのものを人の確認とする |
| 必須チェック | 型チェック、Lint・整形、単体テスト、ビルド（0008） | CI が赤ならマージできない |
| main を最新にしてからマージ | ON | 別々に緑だった PR の組み合わせで壊れるのを事前に防ぐ |
| 強制 push・削除の禁止 | ON | main の履歴を守る |
| 迂回の許可 | なし | AI にも自分にも同じルールを当てる |

## 進め方
1. GitHub Pro に切り替える（自分で行う） — 済（2026-10-26）
2. 今すぐ設定できるもの（PR 必須、強制 push・削除の禁止）を先に入れる — 済（2026-10-26、ルールセット名 `main`）
3. CI のワークフローが入ってジョブ名が決まったら、必須チェックと「最新にしてから」を足す

## 影響
- AI は main に直接 push できず、必ずブランチと PR を通る
- 「人の確認」（docs/harness/model.md）のうち、マージを人だけが行う部分が仕組みで守られる
