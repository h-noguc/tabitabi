技術スタック

アプリ・実行環境・ハーネスの3層に分けて、何を何で実現するかを並べた表。決まったものから埋めていく。

更新：2026-10-26ハーネスの要素は「ハーネスモデル」の図と対応

3つの層

  • アプリtabitabi そのもののコード。言語、API、画面、地図、DB、認証。
  • 実行環境アプリを動かし、守る場所。ホスティング、DB の置き場、秘密情報、バックアップ、開発環境。
  • ハーネス作り方を支える。Issue、仕様、テスト、CI、Claude Code の設定。

下の層の選択が上の層を縛る。DB の置き場が決まるまで DB テストの形が決まらず、ホスティングが決まるまでデプロイと CI のつなぎ方が決まらない。

CI で決めること

観点たたき台決められる時期
1. 何を検査するか型チェック、Lint・整形、単体テスト、ビルド。DB とブラウザ操作は後で決定 0008
2. いつ走らせるかPR ごとが関門。main への push でも事後確認決定 0008
3. 何を必須にするか1 の4つ。ルールセットで強制決定 0009
4. 速さと費用5分以内、キャッシュ、重い検査は分離今決められる
5. 秘密情報読み取り権限のみ、本番の秘密と DB は渡さない決定 0008
6. AIとの関わりPR を作ったセッションが直す。手順と仕組みは提案中一部決定 0008
7. 依存の更新と安全性Dependabot か Renovate、Action の版を固定好み
8. デプロイとの関係PR ごとにプレビュー、main で本番論点4の後

決める順番

  1. 論点3：地図表示と場所検索の提供元
  2. 論点4：DB・認証・ホスティング（アプリと実行環境にまたがる）
  3. 会話ログの保存先（3 の結果に乗せるか）
  4. 細かいもの：AC の書き方、パートナーの Issue の経路、Cursor も使うか

用語

Hono
Web API を書く小さな枠組み。どのホスティングでも動き、API の型を画面やネイティブへ渡せる
Zod
データの形を宣言し、実行時に入口で確かめる。外から来た JSON を信用しないため
React
画面を部品の組み合わせで作る。ネイティブの Expo と同じ書き方
Vite
開発サーバーと本番ビルドを担う
PWA
Web アプリをホーム画面に置けるようにする Web 標準の仕組み
TanStack Query
API から取ったデータの保管・再取得・更新を引き受ける
Postgres
定番のオープンソースの DB。どのクラウドでも動き引っ越しやすい
Drizzle
TypeScript から型付きで DB を扱い、マイグレーションも作る
PostGIS
Postgres に位置の計算を足す拡張。「近くの場所」を速く探せる
PGlite
手元で動く軽量の Postgres。テスト用
claude-code-action
GitHub Actions 上で Claude Code を動かす公式の Action
