データモデル

tabitabi が何を、どんな形で覚えておくか。2人で共有する「行きたい／行った」を、メンバーごとの関心と訪問記録で表す。

初版：2026-10-26判断記録 0010議論したセッション

クラス図

決めたこと

論点決定
2人分の見え方メンバーごとの関心と訪問記録から計算する。2人とも行った、どちらかだけ行った、2人とも行きたい、片方だけ行きたい
「行った」印は持たない。そのメンバーが参加した訪問記録が1件以上あれば「行った」。行ったうえで「また行きたい」も立てられる
訪問記録訪問ごとに1件。日付（空欄可）・参加者・メモから始め、評価や写真は後で足す
閉店場所の営業状況。人ごとの関心とは分ける
共有と自分だけ場所ごとに選ぶ。共有の場所を外すと、追加した人（持ち主）だけの場所に戻る。相手の関心は消え、訪問記録は持ち主の側に残る
削除持ち主が削除するとゴミ箱に入り、戻せる
二重登録共有の中に同じ外部ID、または近い座標で似た名前があれば、登録時に「すでにあります」と出す
最寄り駅・出口座標から計算する付加情報。行く前に、どの出口から行くかを見て決めるため
分類（暫定）Notion の Places DB の形を引き継ぐ。カテゴリ7種（1つ）、コンテキスト6種（複数）、リスト、お気に入り

後で決めること

  • 評価と写真。写真は保存先・費用・位置情報のメタデータを決めてから
  • 分類を決めた経緯の確認（ローカルの会話ログにある）
  • 重複を後からまとめる機能。登録時の防止をすり抜けた重複が出たら
